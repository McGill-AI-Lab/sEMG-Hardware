## Prioritized findings

1. **High: slave ADC has no clock; 16 simultaneous channels cannot work.** U1.CLKSEL52→+3.3V selects internal oscillator (assuming corrected valid power); U1.CLK37 is electrically unconnected. U2.CLKSEL52→DGND selects external clock; U2.CLK37 belongs only to singleton ADC_CLK, with no oscillator or other driver. A visible ADC_CLK label near U1 is not attached electrically (root investigating dangling-label ERC geometry). ADS §9.3.2.5 p50 Table11: CLKSEL0 makes CLK input; CLKSEL1/CLK_EN0 makes CLK tri-state; CLKSEL1/CLK_EN1 outputs oscillator. The reset CLK_EN is0 (CONFIG1 Table18 p67), so even a correctly wired U1→U2 connection needs firmware enabling U1 CLK_EN before bringing U2 through a clock-dependent reset/config sequence. Correct by routing one valid shared master clock to both chips (e.g. U1 CLK37→U2 CLK37 with master CLK_EN1), preserving U1 CLKSEL high/U2 low, then synchronizing via shared START. No implementation performed. Verify with oscilloscope at both CLK pins and paired DRDY alignment.

2. **High/Medium: undriven ADC reset/start/power-down/chip-select controls during MCU reset.** /CS_ADC1,/CS_ADC2,/PWDN,/RESET,/START have MCU GPIO and ADC inputs only, no external bias resistors. No internal ADS pull states are specified by the source. Therefore safe inactive selects and deterministic controls are not established while ESP GPIO are high impedance/reset or when their supply is absent. Both DOUTs can drive if both CS happen low; floating RESET/PWDN can prevent startup; START can run unexpectedly. Add external CS pull-ups to valid ADC DVDD, START pull-down, and deliberate RESET/PWDN bias/sequence chosen with common clock and supplies. A typical10k CS pull-up would draw0.33mA only when asserted at3.3V; this is an example design value, not an existing component. Firmware must configure output values before output-enable, keep only one CS low, reset/configure both devices, enable master clock, verify registers, and apply shared START. Scope startup/reset; inspect actual firmware. The existing independent regulator /EN net has no controller connection (power reviewer handles).

3. **Critical/High underlying power faults prohibit validating digital operation.** Actual U1/U2.DVDD48/50 connect to DGND, while chip DGND33/49/51 connects AGND and ESP grounds connect DGND. These are different nets with no intended reference tie. No assertion that the resulting DVDD is a valid0V or3.3V can be made without an external connection; it is simply not a valid supplied digital domain. ESP output high into inadequately supplied ADC input can forward-bias protection and violate input limits: ADS §7.1 p12 digital absolute bound DGND−0.3…DVDD+0.3; recommended digital input DGND…DVDD. This risk persists even if ADC holds RESET/PWDN low; these controls do not make pins tolerant of an unpowered rail. Correct supply/ground topology first; enforce I/O state until supply established. ADS §11.1 p96 requires analog/digital inputs low before and during supply stabilization. No peripheral-off input tolerance is specified.

4. **Medium/Unverified: module versus dev board hidden dependencies and backfeed.** Official DevKit guide provides three mutually exclusive supply choices (USB,5V header,3V3 header). A complete DevKitC has onboard5V→3V3 LDO and reset/programming circuitry. Thus carrier U3.CHIP_PU3 unconnected is not evidence of a floating WROOM EN if an intact official board is fitted; boot GPIO0/45/46 rely on specified internal and board biases, and no ADC signals use them. Conversely replacing U3 with a bare WROOM would require a new pin map and EN/boot/USB/UART circuitry. Current 3V3 header is tied to both carrier LDO outputs; USB or5V power can add another3V3 source. Do not combine them without designed source isolation. +5V currently has no source in the carrier schematic; this alone does not prevent the legitimate3V3-header powering option. Verify physical board and source isolation before connecting USB and battery together, especially human-worn use.

5. **Unverified: SPI edges/ringing, EMI and bandwidth-dependent CPU/wireless transport.** No PCB exists in project and no firmware was supplied. Pins and nominal throughput are capable, but trace/load capacitance, receiver rise/fall behavior, RF coupling, DMA scheduling, and packet loss cannot be established. Keep conversion data acquisition paced by interrupt/DMA with bounded latency and monitor both chips during bring-up. No actual current overload on ESP pins is established: ADC controls are high-impedance loads (ADS input current max±10uA p16), with unknown capacitive transient load. 40mA source/28mA sink figures in ESP Table6-3 p27 are typical characterization, not blanket per-GPIO absolute safe limits.

## Correct/conditionally correct details

- Distinct CS plus shared DOUT is a supported ADS cascade bus once supplies, clock and control biases are corrected. TI p57 §9.4.2.1, p60 §9.5.1.4.
- DAISY_IN41 grounded and GPIO42/44/45/46 grounded on each ADS are the specified unused digital-pin treatment (ADS pin table p11 and §9.3.2.1 p48). Firmware must leave grounded GPIO configured as inputs or output-low; programming output-high creates contention.
- Shared START38 and shared RESET36 are suitable routes for synchronization/reset, but shared START alone cannot replace missing common CLK. U2 DRDY NC is deliberate and acceptable only after common-clock, matching-configuration synchronization is demonstrated; current omission impairs slave diagnosis.
- Selected SPI pins GPIO10/11/12/13 are natural FSPI CS/MOSI/CLK/MISO functions; GPIO14 is ordinary second CS. GPIO6/7/8/9 are valid controls/DRDY. None is a boot strap (0,3,45,46), USB19/20, or module flash/PSRAM35/36/37. No boot-pin misuse found in this interface. WROOM v1.8 §3.2 pp11–12, §4 pp13–16; official DevKit headers.
- Unused U3 GPIO0/45/46 do not justify adding arbitrary straps: defaults are GPIO0 pull-up,45/46 pull-down (WROOM Table4-1 p13). GPIO3 floats by default and JTAG source dependence applies when eFuse STRAP_JTAG_SEL is set; default eFuse0 ignores it (Table4-5 p16). An installed intact DevKit supplies its own reset/boot circuits. MCU boot cannot be certified without installed revision/eFuse/firmware state.
- DOUT and DRDY are digital outputs, not open-drain buses requiring pull-ups. Do not add an I2C-style pull-up as an ERC fix. ADS DOUT tri-state is controlled by CS; DRDY remains active irrespective of CS and responds to SCLK (§9.4.1.2 pp52–53). Shared SCLK can clear an unselected ADC DRDY; if asynchronous devices/other peripherals are ever introduced, gate clock per TI or explicitly handle events.
- ADC SCLK input itself has Schmitt trigger (§9.5.1.2 p59); lack of an added external Schmitt buffer is not a generic slow-input fault. Clean edges are still required to avoid extra clocks.

ADS p16: VIH≥0.8DVDD=2.64V; VIL≤0.2DVDD=.66V; VOH≥DVDD−.4=2.9V at−500uA, VOL≤.4V at500uA. ESP Table6-3 p27: VIH≥.75VDD=2.475V, VIL≤.25VDD=.825V, VOH≥.8VDD=2.64V and VOL≤.1VDD=.33V (high-Z table condition). Hence ADS→ESP high/low margins are each.425V. ESP→ADS high table-bound margin is0V and low margin.33V. They share3.3V nominal logic; no5V level translation is involved. Actual lightly loaded ESP high likely closer to rail, but do not call that guaranteed positive static margin from the published table. Bench verify VOH and SCLK at ADC input; use good shared supply/ground. These are *not* actual current-design margin claims.

Packet framing/wireless duty and retransmissions add further over-air traffic.

At3.3V corrected supply use safe dead time between chip selects to avoid their output-enable windows overlapping.

Multibyte command decode:4tCLK≈1.953us nominal; at4MHz byte time2us satisfies TI's nominal example (§9.5.2.9 p63). Above≈4.096MHz, include interbyte delays for register commands. At full industrial internal-clock−2.5% tolerance,4tCLK≈2.0032us, slightly exceeding a4MHz byte; derive delays from slowest actual clock or use slower command speed. Ordinary conversion frames may clock faster subject to p17 timings. Do not run free SCLK while deselected (§9.5.1.2.1 p60).
